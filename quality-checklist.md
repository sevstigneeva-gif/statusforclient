# Контроль качества перед выдачей отчета

## Проекты и контекст
- Каждая задача относится к конкретному проекту.
- Отчет сформирован по запрошенному набору досок (весь проект — features + requirements, или только разработка — features); доска management в отчет не попала.
- Каждый предыдущий отчет привязан к тому же проекту.
- Контекст не перетекает между проектами.
- Риски рассчитаны независимо для каждого проекта.
- Планы сформированы независимо для каждого проекта.
- Внешние зависимости явно обозначены как внешние.
- При нескольких проектах принадлежность каждого результата, риска и плана однозначно понятна.

## Данные
- Все фактические утверждения подтверждены актуальными данными Jira.
- Проектные правила из реестра (project-rules.md), если для проекта заданы, применены ко всем выборкам; служебная статистика соответствует отбору.
- Завершенность задач определена по проектному критерию из реестра, если он задан; иначе — по факту закрытия задачи.
- Правила одного проекта не применены к другим проектам.
- Предыдущие отчеты используются для контекста, но не заменяют актуальные данные Jira.
- При конфликте данных приоритет у актуальных данных Jira.
- Ничего не придумано.

## Динамика
- Учтены задачи, переходящие из периода в период.
- Продолжающаяся задача не представлена как новая, если фигурировала в предыдущих отчетах.
- Отражено существенное изменение состояния продолжающихся задач.
- Использован контекст предыдущих отчетов именно того проекта.

## Результаты
- Значимые результаты за период отражены.
- Аналитика, дизайн и предпроектные работы не исключены только потому, что не являются разработкой.
- Связанные задачи корректно сгруппированы; при группировке не потеряны важные результаты.
- Количество пунктов не ограничено искусственно.

## Риски
- Проблемы и риски подтверждены Jira.
- Используется правильная категория; при нескольких критериях выбран наиболее высокий уровень.
- Один общий риск не продублирован для нескольких задач.
- Если риск влияет на несколько задач, все существенные зависимые указаны.
- In Progress сам по себе не считается риском.
- При отсутствии estimate или срока нет предположений.
- Использованы рабочие дни.
- due date и deadline не смешаны.
- Просрочка определена только при наличии соответствующего срока.

## План
- В план включены To Do и подтвержденные In Progress, которые планируется завершить или продвинуть.
- Не все In Progress автоматически попали в план.
- Завершенные задачи не включены в будущий план.
- План не придуман при отсутствии данных.

## Клиентская коммуникация
- Текст понятен заказчику без знания структуры Jira.
- Нет лишнего технического шума.
- Нет финансовых выводов на основании estimate.
- Действия заказчика основаны только на данных Jira.
- Отчет можно сразу скопировать и отправить клиенту.

## Контроль (субагенты, AGENTS.md)
- После сбора данных запущена проверка данных: дубли, пропуски, неверные даты.
- При найденных ошибках данных отчет не готовился — пользователю перечислены проблемы, данные исправлены перезапросом/уточнением.
- Показатели текущего и предыдущего периодов сравнены; названные причины изменений подтверждены данными, неподтвержденные причины не выдвинуты.
- Числа отчета сверены с выводом scripts/working_days.py (границы периода, рабочие дни) и с результатами JQL-выборок.
- Исходные данные не изменялись (Jira — только чтение); файлы .env, пароли и персональные данные клиентов не открывались.
