# Скилл «Статусная отчетность» (jira-status-report) — инструкция для пользователя

## Что это и зачем

Скилл для ZCode, который по одному запросу сам собирает данные из Jira и готовит регулярный клиентский статус-отчет по проекту — готовый к отправке заказчику без правок. Единица анализа — изменения и результаты за период (что сделано, что продолжается, какие риски и планы), а не просто список задач.

Что это дает:

- **Экономит время**: вместо ручного обхода досок и сборки текста — один запрос.
- **Единый формат и качество**: служебная часть для РП + клиентская часть в структуре, понятной заказчику.
- **Честные риски**: просрочки и блокировки подтверждены данными Jira; нет данных — нет предположений; бюджет из оценок не выводится.
- **Память по проектам**: у каждого проекта свои правила (доски, отбор задач, критерий завершенности, терминология, обращение к заказчику). Скилл помнит их в реестре и применяет; правила одного проекта не переносятся на другие.

Структура отчета:

- **Служебная информация** (для РП, не для клиента): скоуп, период, отбор задач, ключевые цифры, допущения.
- **Клиентская часть**: Результаты за период / Проблемы и риски / Изменения по срокам / Следующий период / Нужно от заказчика (этот раздел выводится только при наличии фактов).

## Как запустить

1. Скилл установлен в `~/.zcode/skills/jira-status-report` — ZCode подхватывает его автоматически в новой сессии.
2. Способы запуска:
   - просто попросить в чате: «Подготовь клиентский статус-отчет по Petstory в Jira за 07.09–20.09»;
   - или явно набрать `/jira-status-report`.

## Как это работает (кратко)

1. **Вводные.** Скилл определяет: проект, период, доски, особенности. Для проекта из реестра правил спросит только недостающее (как правило, период); для нового проекта — задаст четыре вопроса и зафиксирует ответы в реестре на будущее.
2. **Сбор данных.** Выгрузки из Jira за запрошенный период с проектными фильтрами отбора. Jira используется только на чтение.
3. **Проверка данных** (субагент «Проверяющий данных»). Ищет дубли, пропуски и неверные даты. Найдены ошибки — скилл останавливается и перечисляет их; отчет не готовится, пока данные не исправлены.
4. **Анализ и отчет.** Связанные задачи группируются в пункты, риски оцениваются по правилам, рабочие дни считает скрипт-календарь. Если есть данные за прошлый период, субагент «Аналитик» сравнивает показатели и объясняет заметные изменения — только подтвержденными фактами, без придуманных причин.
5. **Сверка и выдача** (субагент «Проверяющий отчёта»). Каждое число отчета сверяется с выборками и выводом скрипта, затем проходит чек-лист качества. После этого отчет можно копировать и отправлять.

## Что нужно от пользователя

- Скажите проект и период. Для нового проекта — ответьте на четыре вводных (проект / период / доски / особенности).
- Доступ к Jira через MCP-инструменты окружения; если инструментов нет — скилл попросит выгрузку.
- Новые правила проекта можно просто сказать в диалоге («у нас завершенность — передача в prod-тест») — скилл допишет их в реестр и будет применять дальше.

## Ограничения

- Не финансовая отчетность, не burndown, не разбор бэклога и не внутренний sprint review.
- Нет оценки работ или срока в задаче — скилл не делает предположений, а помечает допущения в служебной информации.
- Данные и доступ: только данные за запрошенный период; не открываются .env, пароли и персональные данные клиентов; исходные данные не изменяются.
